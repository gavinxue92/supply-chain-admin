# 小型供应链运营管理端前后端联调

## Problem Statement

运营人员需要一个可以实际使用的中文管理端，完成登录、改密、产品、分类、媒体、客服和后台账号操作，并与现有后端安全地联调。

## Solution

在仓库根目录交付 Vue 3 运营管理工程，使用 Element Plus 提供桌面优先界面，通过同源代理访问现有后端 `/api/v1`，并在后端启动后完成主要用户流程联调。

## User Stories

1. 作为管理员，我希望登录后台并保持安全会话，以便访问有权限的运营功能。
2. 作为首次登录或密码被重置的用户，我希望修改临时密码，以便获得可继续使用的账户。
3. 作为用户，我希望刷新页面时恢复或重新建立登录状态，以便不丢失可使用的管理能力。
4. 作为管理员，我希望看到与角色一致的导航，以便只访问有权使用的功能。
5. 作为运营编辑，我希望查看产品列表，以便快速了解草稿、上架、下架和归档产品。
6. 作为运营人员，我希望创建产品草稿，以便逐步录入完整产品信息。
7. 作为运营人员，我希望编辑产品草稿，以便修改名称、分类、图片、关键词、排序、规格和客服策略。
8. 作为运营人员，我希望保存已上架产品，以便修改立即对小程序生效。
9. 作为运营人员，我希望上架产品，以便符合条件的商品进入小程序展示。
10. 作为运营人员，我希望下架产品，以便暂停商品展示。
11. 作为管理员，我希望归档产品，以便从常规管理视图中隔离不再运营的商品。
12. 作为管理员，我希望恢复归档产品，以便将商品重新变为下架状态并重新审核。
13. 作为管理员，我希望归档和恢复前看到二次确认，以便避免误操作。
14. 作为运营人员，我希望选择启用的末级分类，以便上架产品符合后端规则。
15. 作为运营人员，我希望录入多个规格及可选参考价，以便展示商品规格和价格。
16. 作为运营人员，我希望使用受限富文本编辑详情，以便保留安全且适合展示的格式。
17. 作为运营人员，我希望上传一张主图，以便产品始终有明确的主展示图。
18. 作为运营人员，我希望上传最多八张轮播图，以便展示产品图集。
19. 作为运营人员，我希望上传详情图和客服二维码，以便复用已确认媒体资源。
20. 作为运营人员，我希望看到上传进度和失败原因，以便处理图片不符合要求或凭证过期的问题。
21. 作为运营人员，我希望查看分类列表，以便了解分类层级、状态和排序。
22. 作为运营人员，我希望创建一级和二级分类，以便保持最多两级的分类结构。
23. 作为运营人员，我希望编辑分类名称、父分类和排序，以便维持分类组织。
24. 作为运营人员，我希望启用或停用分类，以便控制分类是否可用。
25. 作为运营人员，我希望停用一级分类时得到明确反馈，以便理解整棵分类树会被隐藏。
26. 作为运营人员，我希望删除未关联内容的分类，以便清理无效分类。
27. 作为运营人员，我希望分类删除失败时得到停用引导，以便选择安全的替代操作。
28. 作为管理员，我希望读取和保存全局客服，以便统一影响继承全局配置的上架产品。
29. 作为运营人员，我希望为产品选择继承、覆盖或关闭客服策略，以便精确控制产品客服入口。
30. 作为运营人员，我希望覆盖时填写微信号或二维码，以便后端能校验有效配置。
31. 作为管理员，我希望查看后台账号列表，以便了解账号角色和启用状态。
32. 作为管理员，我希望创建运营编辑账号，以便分配不含账号管理权限的工作角色。
33. 作为管理员，我希望一次性查看并复制新账号的临时密码，以便安全交付给目标用户。
34. 作为管理员，我希望重置账号临时密码，以便恢复无法登录或遗失密码的账号。
35. 作为管理员，我希望停用账号，以便立即撤销该账号的后台会话。
36. 作为管理员，我希望停用或重置密码前看到二次确认，以便避免误操作。
37. 作为用户，我希望所有写操作携带当前 CSRF token，以便安全通过后端校验。
38. 作为用户，我希望会话过期时清除登录态并跳转登录页，以便避免继续无效操作。
39. 作为用户，我希望权限不足时看到明确提示，以便理解该操作为何不可执行。
40. 作为用户，我希望字段校验失败时保留表单输入，以便修正后继续提交。
41. 作为用户，我希望后端业务冲突时看到可操作反馈，以便选择停用、修改或取消。
42. 作为用户，我希望日期、金额和状态按后端契约展示，以便避免错误解释数据。
43. 作为桌面用户，我希望使用左侧模块导航、顶部用户区和面包屑，以便快速定位管理页面。
44. 作为平板或小屏用户，我希望主要页面仍可使用，以便无需专用移动端界面也能完成常见操作。
45. 作为联调人员，我希望只使用相对 `/api/v1` 地址，以便开发代理和生产代理保持一致。
46. 作为联调人员，我希望构建和类型检查通过，以便确定工程基础可交付。
47. 作为联调人员，我希望主要页面冒烟测试通过，以便确认高频流程可运行。
48. 作为管理员，我希望使用现有管理员账号完成联调，并创建编辑账号，以便验证双角色权限。

## Implementation Decisions

- 根目录初始化独立前端工程，不使用后端 Mock 双轨实现。
- 前端使用统一 Axios 实例携带 Cookie、注入 CSRF token 和处理 401/403。
- 页面模块包括认证、产品、分类、媒体、全局客服和后台账号。
- 页面按布局、列表、表单和业务操作拆分，复杂产品表单拆为独立组件。
- 所有请求 DTO 和响应 VO 使用严格 TypeScript 接口。
- 列表保留后端原始顺序，不在前端实现分页、筛选或排序。
- 刷新恢复优先依赖后端会话恢复接口；接口尚未上线时重新登录。
- 富文本只允许规定标签和已确认媒体资源。
- 媒体上传遵循授权、直传、确认三阶段。
- 产品状态流转只显示后端允许的操作，并对危险操作二次确认。
- 分类删除返回冲突时引导停用，而不是只显示通用失败。
- 临时密码只在一次性弹窗中展示，不写入普通持久表单和日志。
- 开发和生产使用同源代理，不把后端域名散布在业务代码中。
- 界面只使用中文文案，不引入 i18n 框架。
- 桌面优先，兼容平板和小屏可用性，不承诺完整移动端排版。
- 后端未启动时不开始真实联调或补充 Mock 页面。

## Testing Decisions

- 浏览器端到端流程作为最高测试切面，验证外部可见行为。
- 冒烟覆盖登录、改密、角色菜单、401/403、产品、分类、媒体、客服和账号主要流程。
- 单元测试只在现有工程具备稳定且可复用的业务边界后补充，避免为实现细节编写脆弱测试。
- 构建和 TypeScript 类型检查作为每次交付的基础门禁。
- 冒烟测试使用真实后端，不使用长期 Mock 认证或业务状态。
- 测试账号和密码通过本地环境提供，不提交到仓库。

## Out of Scope

- 后端分页、筛选、排序、审计日志和批量导入能力。
- 跨层级的移动端完整适配。
- 多语言切换。
- 媒体删除能力。
- 独立产品客服后端接口。
- 本地 Mock 数据作为长期运行方案。
- 服务端脚本化富文本格式修复或编辑器替代后端清洗。
- 在刷新恢复接口上线前承诺免登录刷新。

## Further Notes

- 后端地址、Cookie、CSRF、CORS 和对象存储凭证都需要在真实后端启动后最终核验。
- 后端补充会话恢复接口后应更新联调契约和刷新恢复行为。
- 登录后使用现有管理员账号创建编辑账号，测试双角色权限时再切换账号。
