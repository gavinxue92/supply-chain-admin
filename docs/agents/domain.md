# 领域文档

本仓库的工程 Skill 在探索代码库时应如何使用领域文档。

## 探索前应阅读

- 根目录中的 **`GLOSSARY.md`**；或
- 根目录中的 **`GLOSSARY-MAP.md`**（如果存在）：该文件会指向每个上下文的 `GLOSSARY.md`。阅读与当前主题相关的词汇表。
- **`docs/adr/`**：阅读与即将处理的领域相关的 ADR。在多上下文仓库中，还应检查 `src/<context>/docs/adr/`，获取上下文范围内的决策。

如果这些文件不存在，**静默跳过，不要报告缺失，也不要提前建议创建**。`/domain-modeling` Skill 会在术语或决策真正明确后按需创建这些文档。

## 文件结构

单上下文仓库：

```
/
├── GLOSSARY.md
├── docs/adr/
│   └── decisions
└── src/
```

## 使用词汇表中的术语

Issue 标题、重构方案、假设、测试名称等内容涉及领域概念时，应使用 `GLOSSARY.md` 中定义的术语，不要改用词汇表明确避免的同义词。

如果词汇表中尚未包含所需概念，应重新考虑是否引入了不必要的新术语，并可为 `/domain-modeling` 标记可能的术语缺口。

## 标记 ADR 冲突

如果你的方案与现有 ADR 相冲突，应明确指出，而不是静默覆盖：

> _与 ADR-0007（事件溶解订单）相冲突，但值得重新评估，因为……_
