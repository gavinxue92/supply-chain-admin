# ADR 0002：使用 Cookie 与 CSRF 保持运营端会话

## 状态

已确认

## 背景

后端使用可撤销的 Cookie 会话，不使用 Bearer token；写操作需要 CSRF token；刷新后没有可识别登录角色的接口也会影响权限界面恢复。

## 决策

- 浏览器请求携带凭证 Cookie，不把认证信息写入 Local Storage、Session Storage 或地址参数。
- 所有写请求携带 CSRF token 和正确的 JSON 请求头。
- 登录响应只用于当前会话初始化，不作为持久凭证。
- `401` 清除前端登录态并跳转登录页。
- `403` 展示权限或改密提示，不进行无限重试。
- 后端补充会话恢复接口前，刷新时以重新登录作为兜底行为。
- 后端补充会话恢复接口后，刷新时读取当前用户、角色和改密状态。

## 理由

Cookie 与 CSRF 能复用后端现有安全模型，避免引入第二套认证机制。

## 后果

- 开发和生产都应保持同源或精确代理配置。
- 后端新增会话恢复接口是完整刷新恢复体验的前置能力。
- 刷新恢复接口上线前，用户可能需要重复登录。
